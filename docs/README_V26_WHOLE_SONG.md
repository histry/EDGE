# V26 Whole-Song Duration-Aware ChoreoRAG

## 1. Research objective

V26 moves duration planning before motion composition:

```text
complete music
→ variable phrase structure
→ motion-event / duration / transition sequence
→ style-safe Event-RAG retrieval
→ exact whole-song duration alignment
→ per-event SO(3) time reparameterization
→ boundary-aware transitions
→ complete variable-length dance
```

It deliberately keeps V21 and V23 unchanged so the following ablation remains possible:

- V21 fixed 150-frame scheduler;
- V23 post-hoc runtime refinement;
- V26 rule whole-song planner;
- V26 learned whole-song planner.

## 2. Important scientific boundary

The optional planner is trained from **weak pseudo labels**, generated by the frozen V21 router, style/quality/safety scores and V23 duration priors.  Do not describe this as a ground-truth paired music-dance dataset.  The strongest claim is:

> weakly supervised amortized whole-song phrase planning under a frozen style-safe motion knowledge base.

## 8. Train the optional Transformer planner

```bash
export V26_PLANNER_RUN=output/v26_whole_song_planner
bash scripts/run_v26_train_planner.sh
export V26_PLANNER_CKPT=$(cat "$V26_PLANNER_RUN/BEST_V26_PLANNER_CKPT.txt")
```

Suggested acceptance criteria:

```text
event accuracy ≥ 0.65
duration MAE ≤ 10 frames
transition accuracy ≥ 0.60
best epoch ≥ 10
```

These are pseudo-label imitation metrics, not final choreography quality.

## 11. Main ablations

1. fixed V21 150 frames vs V26 full song;
2. fixed phrase count vs variable phrase segmentation;
3. raw event length vs duration-augmented index;
4. uniform SO(3) vs per-event V23 Tau;
5. rule planner vs learned planner;
6. independent phrase scaling vs exact global allocation;
7. without family MMR;
8. without transition refiner.

## 12. Runtime invariants

V26 aborts instead of silently hiding an error when:

- no candidate exists;
- total transition budget is infeasible;
- exact duration allocation fails;
- generated frame count differs from music frame count.

There is intentionally no final `pad_or_trim_motion`.
